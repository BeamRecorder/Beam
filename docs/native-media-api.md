# Native media prototype API

Capture adapters keep terminal errors in a dedicated bounded event slot, so a burst of drop notifications cannot hide a source failure. CPAL capture also stops an input whose sample timeline runs more than two seconds ahead of the session clock; this catches unpaced virtual devices before they can produce an unbounded recording.

On Linux, a PipeWire recording that targets one named output watches that sink's registry identity. Removing the selected sink interrupts its track and records the reason in the manifest, even if PipeWire can route the stream elsewhere. The default-output sentinel continues to follow the system default.

`beam-media-session` is the platform-neutral entry point. `CameraSelection::Disabled` omits the camera, `FirstAvailable { width, height, fps }` discovers the first camera, and `Device(CameraRequest)` requires the chosen ID from `beam_camera::list_cameras`. `AudioSelection::Disabled` omits an audio track, `Default` resolves the current default, and `Device(id)` requires an ID from `beam_audio::list_inputs` or `beam_audio::list_system_outputs`. On Linux, the latter returns a default-output sentinel and stable PipeWire sink names; selecting a sink sets `target.object` for the monitor stream. `MediaSession::prepare` reserves a v2 session layout and attempts each requested source independently; a missing camera is recorded as a failed track in the manifest. `start` releases one shared `StartGate`; `poll` drains bounded source queues into independent GStreamer writers; `stop` closes the gate, halts producers, drains every queued packet, finishes files and returns the final manifest. The caller must poll regularly. The CLI `beam-media-probe` owns that polling loop.

The `capture-engine` JSON-lines protocol can own that polling loop when built with `--features native-media`. `native-media-devices` lists independent camera, microphone and output devices with per-category errors. `native-media-prepare` takes a `config` with `outputDir`, `camera`, `microphone` and `systemAudio`; selections use `{ "mode": "disabled" }`, `{ "mode": "default" }` for audio, `{ "mode": "device", "id": "…" }`, or camera `{ "mode": "first-available", "width": 1280, "height": 720, "fps": 30 }`. `native-media-start`, `native-media-status` and `native-media-stop` return the state, session ID, manifest path, completion flag and track statuses. Polling and finalization run on a dedicated Rust worker so a blocking protocol read cannot starve source queues. Legacy capture commands cannot prepare a recording while the new worker is active, and the worker finalizes an interrupted manifest if the engine exits. Electron's typed `capture` bridge exposes the same operations and assigns the output directory under Studio's project root; renderer callers cannot choose an arbitrary path. The release engine currently builds without this feature and returns `unsupported-operation` for these commands, preserving its existing runtime dependencies. The old Studio recording flow remains the active product path until its project/editor migration and GStreamer bundling are complete.

`AudioSource` and `CameraSource` are the session's shared source contracts. They expose negotiated format, bounded queue depth, nonblocking packet/frame and event reads, and `halt`; the camera contract also exposes the independent latest-frame preview mailbox. CPAL, PipeWire, V4L2, AVFoundation and Media Foundation implement these contracts behind their platform modules. Tests can inject deterministic sources at the session boundary without opening devices; production selection still opens only native sources.

| Source | Linux | macOS | Windows |
| --- | --- | --- | --- |
| Microphone | CPAL/ALSA | CPAL/Core Audio | CPAL/WASAPI |
| System output | PipeWire sink monitor | Core Audio tap through CPAL or a Beam aggregate for duplex outputs | CPAL/WASAPI loopback |
| Camera | V4L2 mmap | AVFoundation video data output | Media Foundation asynchronous Source Reader |

Each adapter emits the same timestamped packets or frames and typed source events. The session, writers, manifest and wgpu preview do not select an OS backend themselves.

The current Beam distribution targets Apple Silicon on macOS 13+, Windows 10/11, and its documented Fedora/Ubuntu Linux packages. The prototype's Core Audio system tap requires macOS 14.2+, so macOS 13 remains on the existing capture path until a separate supported backend is proven. The standalone macOS probe embeds an Info.plist with camera, microphone and system-audio capture reasons; the eventual host app needs its own privacy descriptions. The probe itself does not change the shipped distribution or its minimum OS version.

Camera frames are `VideoFrame<CameraFrame>`. `captured_ns` is the session PTS; `native_timestamp_ns` is present when the backend supplies a trustworthy hardware timestamp. `CameraFrame` owns an `Arc<[u8]>`, so the original device buffer can be returned immediately. `latest_preview` takes the latest frame and can skip older previews without reducing recording throughput. The CLI uploads preview frames on a separate worker so GPU latency cannot hold up session polling. `CameraPreview::update` accepts a caller-owned wgpu Device and Queue, reuses one texture at a constant size and reports its view and PTS. The caller must submit the queue after `update`: wgpu stages `write_texture` uploads until submission. The CLI submits and polls once per frame so those staging allocations are released. The GPU device remains the caller's responsibility. Preview measurements count bytes written during CPU color conversion, the extra CPU row-padding copies, and bytes staged for GPU upload; the report divides these totals by uploaded preview frames. If GPU setup or upload fails, recording still finalizes and `measurements.json` records the preview error and available counters; the CLI exits with an error after saving the media.

Audio arrives as `TimedAudioPacket`: interleaved F32 samples, rate, channels, frames, first sample position, session PTS, and an optional native capture timestamp. CPAL handles microphones on all targets and loopback outputs on Windows; PipeWire handles Linux system output. On macOS, output-only devices use CPAL's tap path. Duplex outputs use a Beam-owned Core Audio process tap and private aggregate device, then pass the aggregate's input through the same CPAL packet conversion and shared queue. This avoids routing a duplex device's microphone into the system-audio track. The aggregate and tap are destroyed when the capture stream stops. Beam maps Core Audio's documented [device permission error](https://developer.apple.com/documentation/coreaudio/kaudiodevicepermissionserror) to `AudioError::PermissionDenied` and its bad-device error to `DeviceUnavailable`; the remaining OSStatus values retain their operation and numeric code. This path compiles for the macOS ARM64 Rust target but still requires a physical permission and audio test on macOS. All callbacks use bounded queues and `try_send`; overflow emits a drop event. Each encoder has its own byte and packet limits.

Linux system audio requests [PipeWire buffer header metadata](https://docs.pipewire.org/structspa__meta__header.html) and forwards its PTS only when it is valid and monotonic. A discontinuity or corrupt header invalidates subsequent native anchors for that recording. Header metadata is optional: a local five-second monitor recording completed without any header PTS, so its system-audio drift remains unknown. PipeWire's [stream time](https://docs.pipewire.org/structpw__time.html) describes the graph clock rather than the capture time of that buffer and is not substituted for a missing PTS.

The shared CPAL microphone/loopback path marks a native clock discontinuity when capture or callback time regresses, capture time exceeds callback time, or capture time leaps more than one second beyond the callback interval. It then omits native timestamps from later packets while continuing to record audio.

The shared `TrackMeasurements` keeps the first valid native anchor even when it appears less than one second after a point without a timestamp. Once a track loses native timestamps or reports a camera/audio clock discontinuity, `nativeClockDiscontinuous` becomes true and its drift in the probe report is null; the raw timing points remain available. Older measurements default the stored flag to false, while the report also detects gaps already visible in their saved anchors. Discontinuities affect only their own track.

Track states in the v2 manifest are `Preparing`, `Recording`, `Paused`, `Completed`, `Failed`, and `Interrupted`. A requested source or writer failure affects its own track and makes `manifest.completed` false. A segment is marked complete only after EOS, file sync and `.part` rename. Writer shutdown uses timed queue and worker waits; a stalled encoder is set to `Null` and reported as a failed track without publishing its `.part` file. If saving `measurements.json` fails after media files finish, the session still attempts to publish an incomplete final manifest with a warning and returns the storage error; a full disk may also prevent that final manifest write, leaving the last partial checkpoint for recovery. Camera and PipeWire source shutdown retain a worker handle after a timeout so a later `halt` can join it if the blocking native read returns; a permanently blocked device still requires an OS-specific cancellation path and hardware validation. `measurements.json` stores native/session anchors sampled once per second, sample positions, drops, observed peak source/encoder queue depths, preview counters, submission latency, and periodic process-tree RSS/CPU samples. Each process sample also includes the cumulative uploaded preview frame count when preview is active, so its cadence can be compared with resource use over time. `probeLoop` records the number and longest duration of session polls and process resource samples; it defaults to zero when loading measurements written before this diagnostic was added. The periodic resource sample timestamp is taken after process enumeration so long samples are placed at their actual completion time. Submission latency is measured from the camera PTS until `queue.submit` and `Device::poll` return; it does not claim display or scanout latency. The probe samples wgpu allocator bytes when the backend exposes a report; this is the live allocation count known to wgpu, not total system GPU usage, and remains null where unsupported. The probe emits camera VP8/WebM and two PCM WAV files. `capture` re-exports the extracted manifest types for compatibility with existing sessions.

Run `cargo run -p beam-media-probe -- devices` to inspect source IDs, then `cargo run -p beam-media-probe -- record --output /tmp/beam-native-session --duration 5`. Use `--no-camera`, `--no-microphone`, or `--no-system-audio` to omit a source intentionally. Ctrl+C finalizes available files and marks running tracks interrupted. `cargo run -p beam-media-probe -- report --output /tmp/beam-native-session` reads the saved manifest and measurements without opening hardware.
The `devices` JSON keeps camera, microphone and system-output lists independent. Its `errors` object reports discovery or permission failures per category, so denying camera permission does not hide audio device IDs. `CameraError::PermissionDenied` distinguishes a rejected camera authorization or access check from `DeviceUnavailable` across the three platform adapters; the session records the error text on the camera track.

The platform boundary is in `beam-camera/src/{linux,macos,windows}` and `beam-audio/src/{linux,cpal_capture.rs}`. Linux camera capture uses V4L2 mmap. The macOS camera adapter now uses `AVCaptureVideoDataOutput` directly, requests permission, selects a device format, requests BGRA output, discards late frames and copies each accepted pixel buffer into a bounded callback queue. The Windows adapter uses a Beam-owned Media Foundation Source Reader in asynchronous mode: one pending read, bounded callback and recording queues, `Flush` cancellation, and explicit media-source shutdown. Both expose the same `CameraCapture` and `CameraSource` contracts. macOS and Windows runner tests and physical privacy, format, unplug and cancellation checks remain required before these backends are accepted. The session, manifest, encoder and preview interfaces remain shared while the adapters change. Hardware validation remains required on each OS and output device class before this replaces Beam's current capture engine.

If a periodic checkpoint cannot be written, the probe interrupts the session and records that cause in the final manifest warnings. A directory or other non-file obstruction at `manifest.partial.json` is left untouched while the final incomplete manifest and measurements are published separately.
