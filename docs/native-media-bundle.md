# Native media GStreamer bundle profile

The prototype loads GStreamer dynamically. The required element factories are `filesink`, `appsrc`, `videoconvert`, `vp8enc`, `webmmux`, `audioconvert`, and `wavenc`. The tested plugin allowlist is `coreelements`, `app`, `videoconvertscale`, `vpx`, `matroska`, `audioconvert`, and `wavenc`, plus the GStreamer core library and runtime dependencies discovered from those exact binaries. Do not include `gst-libav`, `x264enc`, or a whole `bad`/`ugly` plugin tree by default.

The Fedora 44 development host reports GStreamer **1.28.7** for every required factory. `gst-inspect-1.0` reports LGPL for each of the seven plugins; `vp8enc` also depends on libvpx. Version **1.28.7** is the bundle candidate: upstream publishes [Windows MSVC x86_64 and ARM64 installers](https://gstreamer.freedesktop.org/data/pkg/windows/1.28.7/msvc/) and a [universal macOS runtime and development installer](https://gstreamer.freedesktop.org/download/) at that version. The official macOS and Windows x86_64 runtime installers were downloaded on Linux and matched their published SHA-256 digests. Static inspection confirmed the macOS `Versions/1.0/{bin,lib,libexec}` layout and installer-level `Resources/license.txt`, and the Windows `bin`, `lib/gstreamer-1.0`, `libexec/gstreamer-1.0`, and `share/licenses` layout. These observations do not prove a portable bundle. The macOS and Windows packages still need a separate inventory of each bundled binary and transitive library, its exact version, license, notice, source offer where required, and a clean-machine test. The minimum runtime is GStreamer 1.24; pin the same 1.28.7 runtime and plugin set in all three packages if the bundle candidate passes those checks.

The `native-media.yml` workflow installs those official runtime and development packages on macOS and Windows, checks the seven factories, and runs the Rust suite. It has not yet been executed on GitHub. It also builds a release probe and calls `build_gstreamer_macos_bundle.py` or `build_gstreamer_windows_bundle.py` to stage a private runtime from the seven inspected plugins, their linked libraries, a private plugin scanner, and installed notices. Each builder verifies factory origins, excluded factories, binary linkage, the SHA-256 and size of every inventoried file, and a relocated probe launch before publishing an artifact. A separate fresh runner for each OS then downloads that artifact and repeats the private-runtime verification without installing GStreamer; macOS uses a tar artifact to preserve executable permissions. The macOS release probe is linked with header padding so `install_name_tool` can lengthen its load paths. The macOS builder rewrites Mach-O load paths, signs the changed binaries ad hoc, and copies the license text from the official runtime package; that text is not installed inside the framework. The Windows builder follows recursive PE imports and takes required VC runtime DLLs from the installed MSVC redistributable directory when GStreamer does not contain them. Windows 10/11 provides [the Universal CRT as an OS component](https://learn.microsoft.com/en-us/cpp/windows/universal-crt-deployment?view=msvc-170), so the builder records `ucrtbase.dll` as a system dependency. The scripts have Linux-hosted unit tests, but these native workflow steps and the resulting artifacts have **not** been run on macOS or Windows yet. Their successful execution and clean-machine tests remain required before treating the bundles as distributable.

On Fedora 44, `scripts/ci/build_gstreamer_linux_bundle.py --binary <release-beam-media-probe> --output <new-directory>` now stages the probe, the seven plugins, the GStreamer plugin scanner, and the ELF library closure apart from explicitly listed operating-system libraries. It copies installed RPM license notices and writes `inventory.json` with source packages, licenses, hashes, and external system dependencies. `run-probe` sets the private library, plugin, and scanner paths and gives each invocation a fresh registry. The builder verifies the linked library paths and factory origins both before and after moving the staged directory. The Linux bundle is specific to the distribution and ABI used to build it; the inventory is the review input for its package, not a substitute for the legal review of notices and source obligations.

A Fedora 44 build at `/tmp/beam-gst-bundle-final-20260922` contains seven plugins and has no missing installed RPM notices in its inventory. Its `run-probe record` completed camera, microphone, and system-audio tracks in a three-second hardware smoke test; `ffprobe` read 2.993378 s of WebM video and 3.029333 s from each WAV. The eight writer tests also pass with `LD_LIBRARY_PATH`, the plugin path, and the scanner pointed at the staged bundle. In a fresh Fedora 44 container, after installing only PipeWire, ALSA, and DRM operating-system libraries with weak dependencies disabled, both `gstreamer1` and `gstreamer1-plugins-base` remained absent. All seven private factories resolved and the bundled probe launched. This proves Linux loading without a host GStreamer install on that distribution. It does not prove camera/audio device operation inside the container, portability to other Linux distributions, or private macOS/Windows bundles.

After adding common camera permission errors and inventory hash verification, the release probe was rebuilt with all features. A new private Fedora bundle at `/tmp/beam-gst-bundle-20260922-permission` passed staging. Its tar archive was extracted in a fresh Fedora 44 container with only the declared system libraries; the downloaded-layout verifier passed, while both host GStreamer RPMs remained absent.

The workflow now has a Fedora 44 build job for the release probe and private bundle, followed by a separate Fedora 44 clean-container job that downloads the archived bundle and calls `verify_bundle` with no host GStreamer packages installed. The tar artifact preserves executable permissions across the jobs. The clean-container command was repeated locally against the existing release bundle and passed. These two GitHub jobs have not yet run on a hosted runner; their CI status is still open.

For the private package, the [GStreamer macOS deployment guide](https://gstreamer.freedesktop.org/documentation/deploying/mac-osx.html) requires relocating framework library paths after copying the framework into an app bundle and setting the private plugin scanner and plugin path. The [Windows deployment guide](https://gstreamer.freedesktop.org/documentation/deploying/windows.html) allows installing the runtime inside the application's folder; manually selecting only its DLLs requires checking their transitive dependencies. The official guides still show obsolete packaging examples, so the builders must be validated against the pinned 1.28.7 runtime on native runners. The copied notices and library inventories require a legal review; the scripts do not infer a license for each transitive DLL or dylib. Both packages need a clean-machine run with the host's GStreamer installation absent; the current cross-compilation cannot establish that gate.

`scripts/ci/check_gstreamer_profile.py` copies only the seven plugins above into a temporary directory, disables GStreamer's system plugin paths, checks that all seven factories resolve from those copies, verifies that an installed but excluded `videotestsrc` factory is invisible, rejects `x264enc` and `avdec_h264`, then runs the writer tests with this isolated plugin directory. On Fedora 44 / GStreamer 1.28.7, all eight writer tests pass in that profile. This check found the previously omitted `coreelements` plugin used by `filesink`. With `--inventory-output`, it also writes each verified plugin's version, declared license, source path, byte size and SHA-256 digest. The CI workflow uploads this inventory separately from each OS runner. This narrower plugin-profile check still links to the development host's GStreamer libraries; the Linux bundle builder above checks the private runtime separately.

The macOS host app must include `NSCameraUsageDescription`, `NSMicrophoneUsageDescription`, and, for Core Audio taps on macOS 14.2+, `NSAudioCaptureUsageDescription` in its Info.plist. The standalone probe embeds its own Info.plist with these three descriptions in the Mach-O `__TEXT,__info_plist` section; the private bundle verifier checks that they survive relocation and signing. Camera discovery requests AVFoundation permission before opening a device; a CLI run from a terminal can have different privacy attribution from the packaged app. Validate permissions in the packaged app on a clean macOS machine. Windows camera and microphone privacy settings must likewise be tested with the actual packaged executable.

Build verification should load only the private plugin directory using `GST_PLUGIN_SYSTEM_PATH_1_0=` and `GST_PLUGIN_PATH_1_0=<bundle>/plugins`, then run `beam-media-probe record` and independently inspect the three outputs. A missing factory must be a track failure in the manifest. A release package is not complete until the notices and source obligations for its selected runtime are included and the three clean-machine checks pass.
